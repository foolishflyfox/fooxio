# i18n 文件夹

`frontend/src/i18n/` 是前端的国际化模块，集中管理支持的语言、翻译资源及语言与页面 URL 的对应关系。应用通过这里的配置和资源选择当前语言，并向 React 组件提供本地化文案。

## locales

`frontend/src/i18n/locales/` 存放各语言的翻译文本。目录按语言代码划分，例如 `en/`、`zh-cn/`、`ja/`；每个语言目录下使用同名 JSON 文件保存对应文案。`common.json`、`common2.json` 和 `releases.json` 包含界面及版本相关文案，`docs.json`、`docs2.json` 包含文档文案，`seo.json` 至 `seo4.json` 包含相关页面的文案。运行时，这些文件会被加载并合并为该语言的翻译资源，供页面按翻译键取值。英文资源随初始化直接加载，其他语言在需要时按需加载。

翻译以 `en/` 下的 JSON 为原文，由 `frontend/scripts/translate-i18n.mjs` 调用 DeepSeek 生成其他语言的对应文件；DeepSeek 不参与网页运行时的翻译。在 `frontend/` 目录执行：

```bash
# 翻译所有目标语言；默认跳过已经存在的文件
DEEPSEEK_API_KEY=你的密钥 npm run translate:i18n

# 只翻译西班牙语
DEEPSEEK_API_KEY=你的密钥 npm run translate:i18n -- --locale es

# 重新生成西班牙语译文，覆盖已有文件
DEEPSEEK_API_KEY=你的密钥 npm run translate:i18n -- --locale es --force
```

`npm run` 后的第一个 `--` 是分隔符，使后面的 `--locale es`、`--force` 传给翻译脚本，而不是由 npm 解析。还可以用 `--namespace common` 只处理指定的 JSON 文件。翻译脚本会检查译文是否保留英文原文的 JSON 键结构。
