# 从源码运行 Velxio（不使用 Docker）

本文适用于本仓库的开源版：在本机分别启动 FastAPI 后端和 Vite 前端。基础启动不需要数据库、Redis、Nginx，也不需要 Docker。编译不同开发板程序、运行 ESP32 仿真或编译自定义芯片时，再按需安装相应工具链。

> 本指南中的启动脚本支持 macOS / Linux 的 Bash 或 Zsh。Windows 需另行配置环境；Arduino CLI、QEMU 等原生工具需安装对应平台版本。

## 1. 运行结构与版本要求

| 部分 | 本地地址 | 用途 |
| --- | --- | --- |
| 前端 Vite | `http://localhost:5173` | 浏览器界面、热更新；将 `/api` 代理到后端 |
| 后端 FastAPI | `http://127.0.0.1:8001` | 编译、库管理、ESP32 仿真等 API |
| API 文档 | `http://127.0.0.1:8001/api/docs` | 查看后端接口 |

开发环境使用 Git、Node.js **20**、npm **11**、Python **3.12**；编译 Arduino 程序还需 `arduino-cli` **1.x**。下面的脚本会自动安装或启用 nvm、Node、npm、uv、Python 和前后端依赖，不要求系统预装 Python。仓库当前不提交前端 `package-lock.json`，首次安装会从 npm 仓库解析依赖。首次安装需要网络。

在项目根目录检查工具：

```bash
node --version
npm --version
arduino-cli version
```

如果仅想先查看界面，`arduino-cli` 可以稍后安装；没有它时，涉及后端 Arduino 程序编译的功能不可用。浏览器端 AVR/RP2040 等仿真代码由前端 npm 依赖提供，但编译 Arduino 草图仍需相应内核。

## 2. 获取代码

已有本仓库时，直接进入项目根目录即可；新克隆时：

```bash
git clone https://github.com/davidmonterocrespo24/velxio.git
cd velxio
```

普通启动不要求 `--recurse-submodules`。`@wokwi/elements`、`avr8js`、`rp2040js` 均从 npm 安装，板卡图片在 `frontend/public/boards/`。`third-party/` 中的参考仓库不是基础启动依赖。

### 初始化 macOS / Linux 开发环境

在项目根目录或任意目录运行（把路径改为本机仓库位置）：

```bash
source /path/to/velxio/foo-scripts/setup-env.sh
```

若已在仓库根目录，可用 `source foo-scripts/setup-env.sh`。**必须使用 `source`**：脚本需要在当前终端切换 Node 版本、激活 `backend/.venv`。它不会改变当前工作目录。首次运行会在缺少工具时安装 nvm 和 uv；nvm 官方安装器可能向 `.zshrc` 或 `.bashrc` 追加加载代码。脚本会安装 Node 20、npm 11、uv 管理的 Python 3.12，并创建 `backend/.venv`。它不会替换系统默认的 `python3`。

脚本还会安装根目录和 `frontend/` 的 npm 依赖，以及 `backend/requirements.txt` 的 Python 依赖。需要在当前终端使用开发环境时，重新 `source` 即可；启动脚本会自行加载环境。只有对应依赖清单变化、安装目录缺失或首次安装尚未成功时才重装。前端开发命令使用根目录的 `tsx`，因此两处 npm 安装都需要完成。脚本不安装 Arduino CLI 或各开发板内核，这些见第 3 节。

验证当前终端：

```bash
node --version
npm --version
python --version
```

应该分别显示 20.x、11.x、3.12.x。若已有 `backend/.venv` 但不是 Python 3.12，脚本会停止并提示人工处理，不会删除原有环境。

### 分别启动前后端

打开两个终端，在仓库根目录分别执行：

```bash
# 终端 1：后端
bash foo-scripts/start-backend.sh
```

```bash
# 终端 2：前端
bash foo-scripts/start-frontend.sh
```

两个脚本都会自行加载 `setup-env.sh`，也可以从任意目录用绝对路径运行。后端和前端日志分别留在各自终端；按 `Ctrl+C` 只停止对应服务。已有后端占用 8001 端口时，先停止旧进程。

打开前端脚本输出的 Vite 地址，通常是 <http://localhost:5173>。前端启动时会先生成元数据和元件 SVG；需要保留仓库根目录的 `scripts/`。前端默认通过 Vite 将 `/api` 代理到 `http://127.0.0.1:8001`。如果 5173 被占用，实际访问地址以终端输出为准。

### 后端健康检查

后端终端显示 `Application startup complete` 后，另开终端检查：

```bash
curl --noproxy 127.0.0.1 http://127.0.0.1:8001/health
```

开源版正常返回 `{"status":"healthy"}`。

### 可选的后端环境配置

当前开源版的 `backend/.env` 只有一个可配置项：`FRONTEND_URL`。它指定后端允许跨域访问的前端来源，默认是 `http://localhost:5173`；后端也已允许 `http://localhost:5174` 和 `http://localhost:5175`。使用 Vite 的 `/api` 代理时，通常无需修改它。

如果前端改用其他地址，并且浏览器需要直接请求后端 API，尚无 `backend/.env` 时在仓库根目录复制配置样例：

```bash
cp backend/.env.example backend/.env
```

然后编辑 `backend/.env`，把 `FRONTEND_URL` 改为浏览器访问的前端来源，例如 `FRONTEND_URL=http://localhost:5180`，并重启后端。这个配置不会改变 Vite 的监听端口；需要固定前端端口时，在 `frontend/vite.config.ts` 的 `server` 中设置 `port`。`backend/.env` 已被 Git 忽略；开源版会忽略其中的其他旧配置项。

## 3. 安装 Arduino CLI 与开发板内核

可在交互终端运行 `bash foo-scripts/full-setup-env.sh`：它先加载 `setup-env.sh`，再逐项检查 Arduino CLI、下列开发板内核及第 4 节的工具；仅在缺少时询问是否安装。输入 `n` 可跳过，直接按回车默认安装。使用 `bash foo-scripts/full-setup-env.sh --yes`（或 `-y`）可自动确认安装所有缺少的软件，ESP-IDF 也不会单独询问。QEMU 动态库与 ROM 可用个人密钥从项目下载接口获取；脚本不会保存密钥，未设置 `VELXIO_LICENSE_KEY` 时仍需输入密钥。脚本为本机安装 WASI-SDK 34；镜像仍使用 v22。安装在 `backend/.venv/` 内的工具链路径由后端启动脚本自动加载。macOS 安装 ESP-IDF/SDCC 需 Homebrew，Linux 的系统依赖安装目前使用 `apt-get`。

先按照 Arduino CLI 的安装说明将可执行文件加入 `PATH`，再运行：

```bash
arduino-cli version
arduino-cli core update-index
arduino-cli core install arduino:avr
arduino-cli core list
```

`arduino:avr` 用于 Arduino Uno、Nano、Mega 等 AVR 草图编译。按需安装其他内核：

```bash
# Raspberry Pi Pico / Pico W
arduino-cli config add board_manager.additional_urls \
  https://github.com/earlephilhower/arduino-pico/releases/download/global/package_rp2040_index.json
arduino-cli core update-index
arduino-cli core install rp2040:rp2040

# ESP32 系列：不安装 ESP-IDF 时，后端可回退到 Arduino CLI 编译
arduino-cli config add board_manager.additional_urls \
  https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32@3.3.9
```

ATtiny85 还需要 `ATTinyCore:avr@1.4.1`。其索引偶有连接或 TLS 问题；本仓库提供 `backend/board-indexes/package_drazzy.com_index.json`，具体处理方法见 [`backend/board-indexes/README.md`](../backend/board-indexes/README.md)。安装完用 `arduino-cli core list` 确认内核。若启动后端的终端在安装 CLI 前已打开，重新打开终端或重启后端，确保其 `PATH` 中能找到 `arduino-cli`。

## 4. 按需补齐高级功能

| 功能 | 需要额外准备 | 不准备时的影响 |
| --- | --- | --- |
| AVR / RP2040 Arduino 草图编译 | Arduino CLI 与相应内核 | 编译请求失败 |
| ESP32 / S3 / C3 Arduino 草图编译 | 上述 ESP32 CLI 内核，或 ESP-IDF **v5.5.4** + arduino-esp32 **3.3.10** | 无法编译对应固件 |
| ESP32 / S3 / C3 后端仿真 | 与本机系统及 CPU 架构匹配的 Velxio `libqemu` 动态库，以及同目录 ROM | 编译可独立进行，但无法启动这些板卡的后端仿真 |
| 自定义芯片 C → WASM 编译 | WASI-SDK（镜像使用 v22） | `/api/compile-chip/` 报告编译器不可用 |
| 某些其他语言/目标芯片 | 对应本机工具链，例如 `sdcc` | 对应目标的编译不可用 |

### ESP32 编译：两条路径

仅需快速试用时，先安装上一节的 `esp32:esp32@3.3.9` 内核。后端在没有可用 ESP-IDF 安装时可回退到 Arduino CLI。若需要与当前独立 Docker 镜像的 ESP32 编译环境一致，则安装 ESP-IDF v5.5.4（目标含 `esp32,esp32s3,esp32c3,esp32c6`）及 arduino-esp32 3.3.10，并在启动后端前设置本机实际路径，例如：

```bash
export IDF5_PATH=/path/to/esp-idf-v5
export ARDUINO_ESP32_5_PATH=/path/to/arduino-esp32-3
export IDF_PATH="$IDF5_PATH"
export ARDUINO_ESP32_PATH="$ARDUINO_ESP32_5_PATH"
export IDF_TOOLS_PATH="$HOME/.espressif"
```

具体安装方式、版本兼容和编译说明见 [`docs/ESP32_EMULATION.md`](../docs/ESP32_EMULATION.md)。ESP-IDF 安装体积较大；不做 ESP32 编译时可跳过。

### ESP32 仿真：QEMU 动态库与 ROM

运行 `full-setup-env.sh` 时，选择安装 QEMU，并提供在 <https://velxio.dev/license/signup> 申请的个人密钥。脚本会按本机平台下载两份动态库和四份 ROM，保存在 `backend/.venv/toolchains/qemu/`；后端启动脚本会自动指定该目录。目前自动下载支持 macOS Apple Silicon、Linux x86_64 和 Linux ARM64。

当前后端支持从环境变量指定库路径，或从 `backend/app/services/` 自动查找。建议把匹配本机平台的库和 ROM 放在同一目录，再在启动后端前指定：

```bash
export VELXIO_QEMU_PATH=/absolute/path/to/qemu-files
# 该目录应包含 libqemu-xtensa.so / libqemu-riscv32.so（Linux），
# macOS 为 .dylib，Windows 为 .dll；按板型放置相应 ROM。
```

也可分别设置 `QEMU_ESP32_LIB`、`QEMU_RISCV32_LIB` 为动态库的**完整文件路径**。ROM 文件必须与库同目录，常见名称包括 `esp32-v3-rom.bin`、`esp32-v3-rom-app.bin`、`esp32c3-rom.bin`、`esp32s3_rev0_rom.bin`。镜像构建从 `prebuilt/qemu/` 或受许可的下载端点取得这些文件；本仓库默认不携带完整二进制。若要自行构建匹配的库，请按 [`docs_zh/BUILD-QEMU.md`](../docs_zh/BUILD-QEMU.md) 获取**Velxio 对应的 QEMU 源码归档**；直接编译未经修改的上游 QEMU 并不能保证兼容。Linux 上还要安装动态库依赖（镜像列出 `libglib2.0-0`、`libgcrypt20`、`libslirp0`、`libpixman-1-0`、`libfdt1` 等）；其他系统使用对应平台构建。无法加载时检查文件架构、依赖库和后端日志。

### 自定义芯片编译

安装适合本机架构的 WASI-SDK，并在启动后端前设置：

```bash
export WASI_SDK=/absolute/path/to/wasi-sdk
"$WASI_SDK/bin/clang" --version
```

后端会在该目录下查找 `bin/clang`，头文件来自仓库的 `backend/sdk/velxio-chip.h`。若 SDK 装在 `/opt/wasi-sdk`、`/usr/local/wasi-sdk` 或 `~/wasi-sdk`，后端也会自动查找。

## 5. 验证与排障

1. 确认上面的后端健康检查通过。
2. 打开 <http://localhost:5173>，浏览器能加载界面。
3. 打开浏览器开发者工具的 Network 面板，确认 `/api/...` 请求由 Vite 代理且没有连接错误。
4. 若已安装 `arduino:avr`，在界面选择 Arduino Uno，编译一个最简单的 Blink 草图，验证 Arduino CLI 与后端的实际调用链。只有 `/health` 成功不能证明编译工具链已就绪。

| 现象 | 检查方向 |
| --- | --- |
| 前端显示 API 连接失败、`/api` 返回 502 | 后端是否运行在 8001；是否从项目根目录的 `backend/` 启动；端口是否被其他进程占用 |
| `arduino-cli` 找不到或缺少 FQBN | `arduino-cli version`、`arduino-cli core list`；确认后端进程的 `PATH` 与手工运行命令的终端一致 |
| `npm run dev` 在生成元数据或 SVG 时失败 | 重新 `source foo-scripts/setup-env.sh`；确认根目录与 `frontend/` 的 npm 依赖已安装，且根目录 `scripts/` 存在 |
| ESP32 固件可编译但仿真不可用 | 检查 `VELXIO_QEMU_PATH` / `QEMU_*_LIB`、ROM 是否与库同目录、二进制架构和缺失的系统动态库 |
| ESP32 编译失败 | 检查 ESP-IDF/Arduino 内核版本及环境变量；先用 `arduino-cli core list` 验证回退路径 |
| 自定义芯片编译不可用 | 检查 `WASI_SDK/bin/clang` 是否存在并可执行 |

日常开发打开两个终端，分别运行 `bash foo-scripts/start-backend.sh` 和 `bash foo-scripts/start-frontend.sh`；停止服务时各终端按 `Ctrl+C`。如需构建前端静态文件，可在 `frontend/` 执行 `npm run build:docker`；该命令名称虽带 `docker`，实际只是本机前端构建脚本，输出到 `frontend/dist/`，不会启动 Docker。开发热更新无需这一步。
